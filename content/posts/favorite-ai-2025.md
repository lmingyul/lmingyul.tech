## IDE

### Cursor

一款基于 VS Code 二次开发的AI 原生（AI-native）代码编辑器，它能够理解你的整个代码库（Codebase），帮你重构、写代码、改 Bug，甚至直接生成整个功能模块。可以同时进行多个需求的实现，它会启动多个 SubAgent 同时开始帮你干活，可以一边改前端，一边写后端。

它的 Tab 健非常好用，可以预测你的下一步修改的代码在哪里，Tab 一下就能跳到那个位置并把代码修改掉，写代码只需要 Tab Tab Tab ... ... ，以前的常用键是 Ctrl + C ，现在可能是 Tab

它搭配 Claude Opus 一起，开发效率简直跟开了挂一样。

### Windsurf

由 Codeium 团队开发的Agentic AI 代码编辑器（智能体编辑器），目前是 Cursor 最有力的竞争对手之一。

最近我用它比较多，因为便宜🐶，现在周会汇报用到工具也是用这个 Vide Coding 1、2 个小时就做好了。

![](/uploads/posts/favorite-ai-2025/12-image_18.png)

### Claude Code

[Claude Code ](https://code.claude.com/docs/zh-CN/overview)是 Anthropic 官方推出的一款基于 CLI 命令行终端原生（Terminal-Native）的 AI 编程助手 。它可以接 Claude 模型也可以接各家编程大模型的 API。

它与其他编程 IDE 插件不一样的是：

- 它不只是生成代码，它还能执行命令。它可以自己运行 `ls` 查看文件结构，运行 `grep` 搜索代码，甚至运行 `mvn test` 或 `python train.py` 来验证它写的代码是否工作。如果报错，它会读取错误日志，自动修改代码并重试 。
- 它支持超大的上下文窗口（200K tokens），并内置了针对代码库的智能索引。这意味着你可以让它理解整个 Spring Boot 项目的架构，或者让它分析复杂的 PyTorch 训练日志，而不需要手动复制粘贴 。
- 支持 MCP（Model Context Protocol），这意味着你可以给它写插件，让它能连接你的内部数据库或文档系统，或者一些不具备某些功能的模型给他接入 MCP 服务增强模型的能力边界，比如：一个模型不具备搜索能力，给它接入搜索 MCP 服务以及各种技术文档 MCP 服务。

当它搭配 [Claude Code Router ](https://github.com/musistudio/claude-code-router)开源项目，就可以接入国内外提供了 API 的所有模型来驱动官方的 Claude Code 客户端进行编码工作。这个 Router 通过在本地搭建一个代理服务器，拦截 Claude Code 发出的 API 请求，并将其转发到 OpenRouter、Ollama（本地模型）或其他 API 服务商，甚至这个时候就可以接入很多免费的模型。

### 关于 Code Agent 的使用习惯

使用的技巧:

- 自己需求澄清要清晰：
  - 需要有项目背景
  - 实现的功能点，分点说明
  - 设计文档
  - 技术文档

这个部分一般我会先跟某个模型另外的窗口聊清楚再开启后续的流程。这里面就会涉及到一个开源项目 [OpenSpec](https://github.com/Fission-AI/OpenSpec)

OpenSpec 是工作流工具，解决 AI 编程中常见的“幻觉”和“跑偏”问题——即 AI 经常在没有完全理解需求的情况下就开始写代码，导致返工。

**核心理念：先定规矩，再写代码，给 AI 更好的上下文**

**工作流程 (The Workflow)**

OpenSpec 将开发过程分为四个明确的阶段，确保每一步都受控：

![](/uploads/posts/favorite-ai-2025/13-image_7.png)

1. Draft（起草提案）：  
你告诉 AI 你想做什么（例如“添加双因素认证”）。AI 会在 `openspec/changes/` 目录下生成一个提案文件夹，包含 `proposal.md`（改动说明）、`tasks.md`（任务拆解）和 `specs/`（规格变更草案）。
2. Review（审查对齐）：  
你检查 AI 生成的这些文档。如果 AI 理解错了（比如漏了短信验证码），你直接修改文档或让 AI 修改。此时一行代码都还没写，修改成本极低。
3. Implement（执行实现）：  
一旦规格确认，AI 根据 `tasks.md` 开始写代码。因为它已经有了明确的 Spec，所以生成的代码会非常精准。
4. Archive（归档合入）：  
功能开发完成并通过测试后，运行归档命令。该功能的 Spec 会被合并到主文档库（`openspec/specs/`），作为项目的“真理来源”（Source of Truth），供未来 AI 参考。

```txt
在我开始让你写代码之前不要写任何代码，先来理清楚任务的需求，然后帮我把任务需求写入到 requirements.md 中

# 输入你要实现的需求, 一边聊天一边修改
# xxx xxx

我现在需要你按照 SPEC 原则，帮我查创建用户故事；请基于 Constitution 文档，生成用户故事。重点关注以下几类用户：
1.xxx
2.xxx
3.xxx
并增加到 requirements.md 中

接下来请你根据 requirements.md 内容帮我生成设计文档 design.md
重点说明：
xxx
xxx

设计文档需要包含：核心目标、设计架构（架构图）、模块划分等，最好把组件和结构也设计出来，然后列出相关的依赖管理，使用 python 作为后端开发，框架使用 FastAPI，用 uv 作为 python 包管理工具，用 React + Ant Design 作为前端实现工具。

然后不需要生成任何代码，直接根据需求文档 requirements.md 和设计文档 design.md 进行开发任务拆解，生成开发任务文档 task.md 
 
```

使用这个方式，我将 veRL 框架的全英文文档全部翻译成了中文的文档以及周报整理生成工具。

针对模型的不同特性，在不同的编码过程就需要使用不同的模型来工作，比如：

- 使用 Gemini 3 Pro 做需求分析、任务编排
- 使用 Claude Opus / Sonnet 做每个任务的具体编码实现以及单元测试的验证
- 最后使用 OpenAI Codex 做代码 Review

### Zed

[https://zed.dev/](https://zed.dev/)

> Zed 是一款开源的高性能代码编辑器，专为追求极致速度和协作体验的开发者设计 。它由 Atom 编辑器和 Tree-sitter 的原班人马开发，底层基于 Rust 语言构建，利用 GPU 加速渲染来实现瞬时响应 。

它里面也深度集成了 AI 能力。它原生支持 GitHub Copilot，并允许开发者连接 OpenAI、Anthropic (Claude) 或 Ollama 等模型

因为它启动速度很快，一般我是用到当做文本编辑器的替代，它比 Notapad ++ 、sublime text 4 这类的编辑器启动速度要快很多，可以很轻松的打开几百兆的 Json 文件。

### Warp 终端

> Warp 是一款基于 Rust 语言开发的现代化、AI 原生的终端（Terminal）应用。

它最大的特点是完全抛弃了传统终端（如 iTerm2, macOS Terminal）那种“纯文本流”的交互逻辑，而是像一个代码编辑器（IDE）一样工作。它把终端的每一次输入输出都变成了一个个可交互的“块（Block）”，并深度集成了 AI 能力。每次对话可以开启一个 AI Agent 对话 Session，每次输入的命令有补全，执行命令时会给你提建议，终端报错也会给你自动生成修复命令，你也可以完全开放权限给它，它可以做到很多事情，但有时候也会很危险（命令行权限很高）

# 总结

AI 工具有很多，每天都在更新变化，最重要的是使用 AI 的人水平、能力怎么样。想用好 AI 就要敢于用 AI，摆脱 AI 羞耻心态，觉得用 AI， AI 帮自己完成工作就代表自己的能力不行，其实用好 AI 也是一种能力，而且是未来的一种很重要的能力。

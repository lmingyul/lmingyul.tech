# 什么是 Graph RAG

> 基于知识图谱的检索增强技术。将知识图谱与检索增强生成相结合的方法。利用大模型从非结构化的文本中提取实体，关系和摘要，构建知识图谱，然后利用图结构进行高效的检索和问答
>
> [https://arxiv.org/abs/2404.16130](https://arxiv.org/abs/2404.16130)

![](/uploads/posts/graph-rag-notes/01-image-1.png)

# 相比传统的 RAG，Graph RAG 的优势是什么

- 传统的 RAG 偏重局部文本匹配，忽略了整体数据的全面理解，有时候也会给大模型引入语义幻觉
  - 比如：保温大棚 和 保温杯，这 2 个在语义上是存在相关性的，但是如果都作为大模型生成的外部知识的话就会给模型引入幻觉
- 不仅回答了问题的直接答案，还可以从上下文中提取相关信息进行补充，可以通过实体层级特征增强相关性
- 擅长处理针对超长文档的复杂提问，可以基于上下文关系进行推理，更准确地识别相关信息。传统 RAG 中 chuck 彼此是没有联系的，是孤立的，在跨文档问答上表现不好
- 在答案的多样性上表现优于传统的 RAG，还提供基于 Graph 视角上的 embedding 来补充召回特征

# Graph RAG 工作流程

- **数据索引阶段**（建立知识图谱）
  - 实体和关系提取：使用 LLM 从文本或其他形式的内容中提取到实体及实体间的关系，并给实体和关系生成对应的描述
  - 摘要生成：为每个实体和关系生成摘要
  - 社区检测：利用图统计信息，提取图的层次化社区结构
  - 向量嵌入生成：给切分好的文本片段、实体和关系生成嵌入向量
  - 生成 Parquet 后缀的结果文件：将提取到实体、关系、摘要和社区结构等数据，以 Parquet 格式存储
- 检索查询阶段：
  - 查询匹配：根据用户的查询，在社区摘要中寻找答案
  - 答案生成：使用 LLM 基于匹配的内容和问题生成最终答案

## 步骤三：关系挖掘

简单地说就是找出图谱节点之间的边

- “维克托·迈尔-舍恩伯格是《大数据时代》一书的作者。”
  - 实体A：维克托·迈尔-舍恩伯格（人）
  - 实体B：《大数据时代》一书（书籍）
  - 关系：“是….的作者

除了要找出实体之间的关系，还需要判定关系的深浅

计算实体的 level 和 degree 值，用于优化查询和推理

- level 值（等级）：用于衡量实体在知识图谱中的重要程度
  - 指的是：实体在知识图谱中的层次和深度
  - 通过 **图算法**（如近邻中心算法、PageRank 算法）计算或社区发现算法得出
    - 社区检测：实体可以根据其在网络中的连接情况被划分到不同的社区中，通常来说，位于中心的节点会被认为是更为重要的。
    - PageRank：类似于网页排名算法，节点的得分与其直接连接的节点的得分有关，
      重要节点会因为连接到其他重要节点而具有更高的得分。

- degree 值（度）：用于衡量实体之间的连接度
  - 一个节点在图中与之直接相连的边的数量，表示该实体在知识图谱中的连接性
    - 入度：指向该节点的边的数量
    - 出度：从该节点出发的边的数量
  - 度数越高，说明实体越重要

从文本中识别出实体之间的关系（以三元组表示）：

- 维克托·迈尔-舍恩伯格与《大数据时代》之间的关系：“是作者”
  - 大数据时代<->维克托·迈尔-舍恩伯格（是作者）
- 肯尼斯·库克耶与《大数据时代》之间的关系：“是作者”
  - 大数据时代<->肯尼斯·库克耶（是作者）
- 《大数据时代》与数据科学之间的关系：“探讨”
  - 大数据时代<->数据科学（探讨）
- 《大数据时代》与数据分析之间的关系：“阐述”
  - 大数据时代<->数据分析（探讨）

度数可以通过计算图中每个节点的边数来获得：

- 大数据时代：度数为 **4**（它与四个实体都有关系，分别是维克托·迈尔-舍恩伯格、

- 核心实体
- 重要关系

# Graph RAG 的原理

核心原理就 2 个：索引（Index，**核心**）和 检索（Query）

![](/uploads/posts/graph-rag-notes/03-image_4.png)

## 索引流程原理（重点）

> 从原始文本中提取实体，构建知识图谱、搭建社区层次结构、生成社区摘要，方便在执行检索时利用这些结构

### 数据类型

- **输入文档 Document**，可能是：
  - csv 文件中的某一行
  - 独立的一个 txt 文件
- **文本块 TextUnit**：一段要分析的文本
  - 文本的大小、重叠度都可以进行配置
- **提取的实体 Entity**
  - 人、地点、事件等
- **实体之间的关系 Relationship**
- **协变量 Covariate**
  - 表示提取到的声明信息，可能会包含有时间限制的实体描述
- **社区报告 Community Report**
  - 一旦生成实体，就会执行层次化 的社区检测，并为这个社区层次结构生成社区报告
- **布局信息 Node**
  - 已嵌入和聚类的**实体**的渲染图视图布局信息
  - 已嵌入和聚类的**文档**的渲染图视图布局信息

![](/uploads/posts/graph-rag-notes/04-image_5.png)

### 文本单元切分（**Compose TextUnits**）

输入文档被切分转换为小文本单元 TextUnit（如 300 个token，并设置一定的重叠的部分，确保在分块的过程中尽可能保留上下文信息），这些文本单元用于实体和关系的提取，并作为提取知识实体、关系的来源引用。

![](/uploads/posts/graph-rag-notes/05-image_6.png)

### **图谱抽取（Graph Extraction）**

**分析每个文本单元 TextUnit，然后提取实体、关系和声明。**

![](/uploads/posts/graph-rag-notes/06-image_7.png)

图谱提取阶段包括多个步骤：

- **实体识别**（Entity Extraction）：通过 prompt 让大模型进行实体提取
- **关系挖掘**（Relationship Extraction）: 通过 prompt 让大模型进行关系提取
- **实体和关系总结**（Entity & Relationship Summarization）：
  - 将实体及关系这些列表总结成一个实体和关系的单一描述
  - 通过要求 LLM 提供一个简短的总结来完成，从而实现所有的实体和关系都有一个简洁的单一描述。<实体 A，关系，实体 B>
- **实体消歧（Entity Resolution）**：
- Claim Extraction & Emission：从源 textunit 提取出协变量，这个操作是可选的

### 图增强（Graph Augmentation）

![](/uploads/posts/graph-rag-notes/07-image_8.png)

- 社区检测：
  - **使用层次化的 Leiden 莱顿图算法生成实体社区的层次结构**，对上一步构建好的图应用递归的社区聚类，直到我们达到社区大小的阈值，可以提供一种在不同粒度级别上导航和总结图的方法。
- 图嵌入
  - **使用 Node2Vec 算法可以生成向量表示，可以在查询阶段提供一个额外的向量空间，用于搜索相关概念。**

### 社区总结（Community Summarization）

- 生成每个社区的报告，提供对图的高层次理解。在社区数据的基础上进一步构建，并为每个社区生成报告。这为在图的不同粒度级别上提供了对图的高层次理解。

例如，如果社区 A 是最高层级的社区，我们将得到一个关于整个图的报告。如果社区是低层级的，将得到一个关于本地集群的报告。

![](/uploads/posts/graph-rag-notes/08-image_9.png)

- **生成社区报告**
  - 使用LLM为每个社区生成摘要，报告包含执行概览，并引用社区子结构中的关键实体、关系和声明。
- **总结社区报告**
  - 每个社区报告随后通过LLM进行总结，以供简写使用。
- **社区嵌入**
  - **通过生成社区报告、社区报告摘要和社区报告标题的文本嵌入来生成社区的向量表示。**

### **文档处理（Document Processing）**

**对文档进行知识表示，并形成文档图**

![](/uploads/posts/graph-rag-notes/09-image_10.png)

- **首先是将文档链接到文本单元 TextUnit**，将每个文档与第一阶段创建的文本单元关联起来，能够理解哪些文档与哪些文本单元相关。
- **其次是文档嵌入，使用文档切片的平均嵌入来生成文档的向量表示。**
  - 具体地，重新分块文档，不重叠块，然后为每个块生成嵌入，创建这些块的加权平均值，按token计数加权，并将其用作文档嵌入
  - 然后基于这种文档表示，能够理解文档之间的隐含关系，并帮助生成文档的网络表示。

## 检索流程原理

> 核心思想：从用户的输入提取出实体，然后查询知识图谱，构建出子图形成上下文，最后送入大模型完成生成任务

### 伪代码

```py

    # 提取实体

        query_str, graph_rag_context, llm)

```

### 图检索

### Global Search 全局搜索

**通过利用社区摘要，对整个语料库进行整体问题的推理**，利用大型语言模型（LLM）生成的知识图谱来组织和聚合信息，以回答需要跨数据集聚合信息的查询。

使用 LLM 生成的社区报告集合作为上下文数据，以 **map-reduce** 方式生成响应。

根据查询的粒度，选取社区的级别进行信息检索，查询相关社区及其摘要

- 在 map 步骤中（**拆分子问题**），社区报告被分割成预定义大小的文本块。每个文本块用于生成包含点列表的中间响应，每个点都有相应的数值评分，表示该点的重要性。使用 LLM 针对每个社区的摘要，生成部分回答
- 在 reduce 步骤中（**聚合结果**），将多个相关社区的部分回答综合，并将它们聚合起来，消除冗余，保证逻辑连贯，作为生成最终响应的上下文。

### Local Search 局部搜索

> 通过扩展到特定实体的邻居和相关概念，对特定实体进行推理。

利用**知识图谱中的结构化数据**和**输入文档中的非结构化数据**结合，基于实体进行推理

- **首先识别与用户输入语义相关的知识图谱中的实体集合。这些实体作为访问知识图谱的入口**，可以提取更多相关信息，如相关实体、关系、实体协变量和社区报告
- 其次，从原始输入文档中提取与已识别实体相关联的相关文本块。然后，这些候选数据源将被优先排序和过滤，以适应预定义大小的单个上下文窗口，用于生成对用户查询的响应。

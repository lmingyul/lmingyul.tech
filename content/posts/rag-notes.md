# 什么是 RAG

> Retrieval Augmented Generation （检索增强⽣成），RAG 技术是⼀种结合知识检索与基于预训练⽣成的⾃然语⾔处理（NLP）⼤模型架构。

RAG 这个技术由 Facebook AI 于 2020 年提出[**Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks**]，旨在提升⽣成式模型在处理开放域问答、对话⽣成等复杂任务中的性能。RAG 通过引⼊外部知识库，利⽤检索模块（Retriever）从⼤量⽂档中提取相关信息，并将这些信息传递给⽣成模块（Generator），从⽽⽣成更准确且有⽤的回答。

![](/uploads/posts/rag-notes/01-image.png)

**RAG** 模型的核⼼思想在于通过检索与⽣成的有机结合，补充外部信息，弥补⼤模型在处理领域问题和实时任务时的不⾜。

简单的说：**任何可以帮助大模型获取有效信息的技术都可以被成为 RAG**

# 为什么需要 **RAG**

## 在 LLM 中存在以下问题

- 模型的生成是基于训练当时公开的互联网以及开源数据，这些数据无法覆盖特定领域或高度专业化的内部知识，且这些数据**容易过时**，**无法实时**根据最新的信息以及数据去更新模型
- 更新模型知识库就需要进行新数据训练，而重新训练非常困难，既要保证新数据的质量，其次新训练也需要引入旧数据一起混合训练（防止出现**模型遗忘**的问题）
- 模型因为是基于概率生成的文本，生成容易出现**幻觉问题**，输入有时候会不合理
- 私域数据设计到数据安全性以及隐私性也无法直接当成参数给大模型训练使用
- 模型输出的结果**缺乏解释性**，**无法追溯结果的来源**以及真实性

RAG 的出现解决了这些问题，通过将非参数化的知识库、文档与大模型结合，在大模型生成内容之前，实时先去检索与用户输入相关的信息，弥补模型在知识专业性和时效性上的不足，减少生成不确定性，在确保数据安全的同时，充分利用领域知识和私有数据，

- **RAG 类似于开卷考试**
- **模型 Fine-tune 类似于考试前提前先去学专门的知识，类似于闭卷考试**

# 传统 RAG

## 传统 RAG的技术流程

![](/uploads/posts/rag-notes/02-image.png)

RAG 标准的技术流程是由 **索引 、检索、生成** 三个核心阶段组成的，结果输出质量的高低取决于数据质量和检索策略

- **索引（数据准备）**：通过处理多种来源多种格式的文档提取其中文本，然后进行数据清洗，再将其切分为标准长度的文本块（chunk），并进行嵌入向量化（embedding），向量存储在向量数据库（vector database）中
  - **识别数据。首先，将各类数据源及其格式（如书籍、教材、领域数据、企业文档等，txt、markdown、doc、ppt、excel、pdf、html、json 等格式）统一解析为纯文本格式**
  - **提取数据并清洗。接着，根据文本的语义或文档结构，将文档分割为小而语义完整的文本块**（chunks），确保系统能够高效检索和利用这些块中包含的信息
  - **数据向量化。然后，使用文本嵌入模型**（embedding model），将这些文本块向量化，生成**高维稠密向量**，转换为计算机可理解的语义表示
  - **存储到数据库（索引）。存储的数据库有多种选择，一般可以常用向量数据库。当数据存储在向量数据库** (vector database) 时，会构建索引，将 embedding 生成的向量存储到内存或磁盘进行存储和索引，完成知识库的构建。这一流程成功将外部文档转化为可检索的向量，支撑后续的检索和生成环节。
- **检索（数据召回）**：用户输入的查询（query）被转化为向量表示，通过相似度匹配从向量数据库中检索出最相关的文本块。
  - 关键词检索：类似于 ES
  - 向量检索：
    - 用户输入的问题通过同样的**文本嵌入模型**转换为向量表示，将查询映射到与知识库内容相同的向量空间中，然后进行语义检索
      - 前提：相似的向量在向量空间中相互靠近，然后通过近似最近邻（ANN）搜索获取相似的信息
    - 通过**相似度度量方法**，根据相似度（余弦相似度）排序，检索模块从向量数据库中筛选出与查询**最相关的前 K 个文本块**，这些文本块将作为生成阶段输入的一部分
      - 通过相似性搜索，检索模块有效获取了与用户查询切实相关的外部知识，为生成阶段提供了精确且有意义的上下文支持。
- **生成（答案生成）**：检索到的相关文本与原始查询共同构成提示词（Prompt），输入大语言模型（LLM），LLM 基于这些输入生成最终的回答，确保生成内容既符合用户的查询意图，又充分利用了检索到的上下文信息，使得回答更加准确和相关，充分使用到知识库中的知识。通过这一过程，RAG 实现了具备领域知识和私有信息的精确内容生成。

## 传统的 RAG 会面临的问题

- **依赖检索模型的质量和精确度**。自然语言天然复杂性很高，检索技术本身自带模糊性，多种因素就会导致检索出来的知识块存在大量无用的噪声数据，影响模型生成的质量
- **依赖现有的知识库的规模**
  - 如果知识库规模太小，覆盖面不够大就可能无法满足需求
  - 如果知识库规模太大，文本切分出来的数量就变多，会导致在做向量相似度匹配时涉及到 rank 排序的问题，准确度会降低
- **存在性能问题**。比纯粹大模型推理耗时更长，无法满足对延时要求高的场景
- **会受到上下文窗口的限制**
  - 检索到的文本加入到输入中，回答的准确性会随着文本长度的增加而降低
  - 不能无限制地召回很多的数据。如何在有限的 token 窗口中携带更多相关的外部信息，是需要注意的问题
- **当输入问题不在知识库范围内时，检索匹配度就会变低的问题**，无法精准回答
- **跨文本段信息**无法回答。
- 在**需要推理的复杂查询**中表现不佳。简单的相似度的检索无法对实体之间的关系进行推理和判断。

英伟达在 Hugging Face 开源 Nemotron-Labs-Image-30B-A3B：30B 总参数、3B 激活的 MoE 自回归图像模型，是 VisualCreation 框架的光栅渲染引擎。框架主张“像素即代码”，图像模型出素材、SVG/HTML 出文字与结构，再由 Agent Harness 规划、渲染、视觉检查和局部返工。 [\[21\]](https://huggingface.co/nvidia/Nemotron-Labs-Image-30B-A3B)

![图源：arxiv.org 论文首图](https://arxiv.org/html/2611.34576v1/Six_Memory_Strategies_for_Hiring_Assistants.png)

论文面向多会话招聘助手，提出 OKF 索引的情节记忆来组织互动，并通过提示反思或强化学习学到可复用的“决策程序”。实验对比无记忆、全历史上下文与对话搜索，并评测 Jev 类模型做索引导航，以及用 GPT-5.6 Luna 作为 GPT-5.4 的低成本替代。 [\[29\]](https://arxiv.org/abs/2611.34576)

### C2 ★★★★☆ Agentic Waterfall：用意图驱动的信息发现，把推荐控制权还给用户（11-26）

〔C·搜索与智能体意图决策〕

![图源：arxiv.org 论文首图](https://arxiv.org/html/2611.34407v1/figures/waterfall-interaction-illustrated-v3.png)

论文形式化“Agentic Waterfall Feed”问题：用户主动指定推荐方向，系统同时从显式请求与浏览行为推断其变化中的需求。方案用一个语言模型控制器维护持久用户状态，并协调内容检索、排序与状态更新，另发布数据集与回放式评测协议。 [\[30\]](https://arxiv.org/abs/2611.34407)

### C3 ★★★☆☆ Welfare-Enhancing Mechanism Design for Agent Ecosystems：Agent 先选内容源、再看文档（11-26）

〔C·搜索与智能体意图决策〕

![图源：arxiv.org 论文首图](https://arxiv.org/html/2611.33627v1/fig3_mechanism_banner.png)

论文研究 Agentic Web 中的多智能体内容市场：用户 Agent 在看不到文档前，只能依据各内容 Agent 提交的 profile 决定向谁检索。作者构建 WildRegistry 仿真框架与基准，分析多个内容 Agent 竞争有限曝光时的策略与福利。 [\[31\]](https://arxiv.org/abs/2611.33627)

# E. 论文精选

## 搜索、排序与推荐

### E1 ★★★★★ 阿里 LazUnirec：LoRA-MoE + 不确定性估计，把召回与排序塞进同一骨干（11-26）

〔E·搜索、排序与推荐〕

*🏛 阿里巴巴 · 见论文 · arXiv 2611.32590 · 11-26*

阿里提出 LazUnirec，在多场景推荐中统一召回与排序：用 LoRA 调制注意力 + 任务自适应稀疏 MoE 构建共享/私有参数，并用不确定性估计引导梯度更新方向。系统已上线多场景，线上 A/B 验证有效。 [\[40\]](https://arxiv.org/abs/2611.32590)

- **方法**：LoRA 调制注意力 + 任务自适应稀疏 MoE + 不确定性估计引导梯度
- **结果**：已上线多场景系统，线上 A/B 有效

### E2 ★★★★☆ Etsy SIDECAR：draft + tree-attention 单次前向，替代 L 次 beam search（11-26）

〔E·搜索、排序与推荐〕

*🏛 Etsy · 见论文 · arXiv 2611.32855 · 11-26*

Etsy 针对 SID 生成式召回的固定 L 次顺序解码开销，提出 SIDECAR：先用 draft 候选，再用 tree-attention 一次给整棵树打分，并给出精确 top-K 认证与分支定界回退。模型较 sharp 时只需少量调用即可返回精确 top-K。 [\[41\]](https://arxiv.org/abs/2611.32855)

- **方法**：draft 候选 + tree-attention 单次打分 + 精确 top-K 认证
- **结果**：替代 L 次顺序解码，模型 sharp 时少量调用返回精确 top-K

### E3 ★★★★☆ 腾讯 OmniEVIE：4.5B 多向量嵌入，百万级记录单线程 54.2ms（11-26）

〔E·搜索、排序与推荐〕

![图源：arxiv.org 论文首图](https://arxiv.org/html/2611.32203v1/figures/fig1_overview.png)

*🏛 腾讯 · 见论文 · arXiv 2611.32203 · 11-26*

腾讯发布 4.5B 多向量嵌入模型 OmniEVIE，统一文本、图像、视觉文档、视频与工具检索，每条记录压缩到 128×int8×d64（9,472 字节）。MMEB-V3 得 60.06，百万级记录单线程查询 54.2ms，比 4096 维单向量精确检索快 11.1 倍。 [\[42\]](https://arxiv.org/abs/2611.32203)

- **方法**：多向量嵌入 + 128×int8×d64 压缩索引
- **结果**：MMEB-V3 60.06；百万级单线程 54.2ms；比 4096 维单向量快 11.1 倍

### E4 ★★★★☆ OneQuery：多语言电商查询理解的统一序列到结构生成（11-26）

〔E·搜索、排序与推荐〕

![图源：arxiv.org 论文首图](https://arxiv.org/html/2611.33653v1/three_stages.png)

*🏛 作者单位见论文（电商工业界） · Mingyu Zhang, Jiejie Qin, Jianhui Ji 等 · arXiv 2611.33653 · 11-26*

多语言电商搜索需要把跨语言 query 转成标准化语义表示。OneQuery 用领域大模型把语言识别、拼写纠错等四个查询理解子任务统一成序列到结构生成，减少传统多任务管线的误差累积与维护成本。 [\[43\]](https://arxiv.org/abs/2611.33653)

- **方法**：单模型序列到结构生成，统一语言识别/纠错等四个子任务
- **结果**：减少子任务级联误差与维护成本，支持多语言电商搜索

### E5 ★★★☆☆ Amazon MELODI：pool-then-similarity 与 similarity-then-pool 的等价条件（11-26）

〔E·搜索、排序与推荐〕

![图源：arxiv.org 论文首图](https://arxiv.org/html/2611.31940v1/framework.png)

*🏛 Amazon · 见论文 · arXiv 2611.31940 · 11-26*

Amazon 提出相似度-身份解耦的轻量排序框架 MELODI，证明当相似度算子对 history 线性时，更廉价的 pool-then-similarity 与 similarity-then-pool 等价。两个大规模工业数据集上 AUPRC/NDCG/recall 不低于 target-aware 基线，大候选数下延迟更低。 [\[44\]](https://arxiv.org/abs/2611.31940)

- **方法**：相似度-身份解耦 + pool-then-similarity 等价性证明
- **结果**：AUPRC/NDCG/recall 不低于 target-aware 基线，大候选数下延迟更低

### E6 ★★★☆☆ PACS-FedRAG：联邦 RAG 的自适应客户端选择，兼顾隐私与检索成本（11-26）

〔E·搜索、排序与推荐〕

![图源：arxiv.org 论文首图](https://arxiv.org/html/2611.33890v1/fig1.png)

*🏛 作者单位见论文 · Ali Shams Saryazd, Abolfazl Gandomi · arXiv 2611.33890 · 11-26*

联邦 RAG 需要从分布式语料检索证据，但向所有客户端广播查询会放大检索负担与查询暴露。论文提出在线选择器 PACS-FedRAG，综合扰动后的语义画像、证据反馈、延迟、传输成本与探索。 [\[45\]](https://arxiv.org/abs/2611.33890)

- **方法**：基于扰动语义画像与证据反馈的在线客户端选择
- **结果**：10 客户端选 3 的设置下 evidence overlap 0.372、answer accuracy 0.287

### E7 ★★★☆☆ ConTra：用前缀生成做上下文检索，兼顾向量搜索与重排（11-26）

〔E·搜索、排序与推荐〕

*🏛 作者单位见论文 · Jiajun Hou, Jingbang Chen · arXiv 2611.34366 · 11-26*

长文档被切成独立 chunk 后，常丢失用于定位与排序的上下文。ConTra 提出用前缀生成来训练上下文检索：既让前缀可被向量搜索使用，也能被文本重排器读取，避免只把上下文编码进向量导致重排不可见。 [\[46\]](https://arxiv.org/abs/2611.34366)

- **方法**：为 chunk 生成可检索、可重排的上下文前缀
- **结果**：同时服务向量搜索与文本重排，减少上下文丢失

### E8 ★★★☆☆ CA-RAG：面向合规长文的约束对齐检索（11-26）

〔E·搜索、排序与推荐〕

![图源：arxiv.org 论文首图](https://arxiv.org/html/2611.33497v1/Figures/Fig-1_v2.png)

*🏛 作者单位见论文 · Vimal Kumar, Meghana Kshirsagar, Conor Ryan · arXiv 2611.33497 · 11-26*

常规 RAG 按语义相关性选证据，但合规敏感的长文生成还需要支撑强制性结构条款。CA-RAG 在证据选择前，把本体导出的结构约束与政策知识图谱关系注入分节查询。 [\[47\]](https://arxiv.org/abs/2611.33497)

- **方法**：分节查询 + 本体结构约束 + 政策知识图谱关系
- **结果**：人工标注证据集上检索指标一致提升

### E9 ★★★☆☆ MKGE：用共享多模态概念 grounding 用户偏好（11-26）

〔E·搜索、排序与推荐〕

![图源：arxiv.org 论文首图](https://arxiv.org/html/2611.34436v1/motivation_concept_path_v34.png)

*🏛 作者单位见论文 · Ao Xu, Jinhui Huang, Wenqiang Tang 等 · arXiv 2611.34436 · 11-26*

多模态推荐通常把用户偏好编码成与单个 item 绑定的隐信号，难以跨 item 复用。MKGE 从商品图像与标题诱导领域自适应概念词表，把用户历史 grounding 到可寻址概念上，并联合建模直接 user-item 证据与概念中介偏好。 [\[48\]](https://arxiv.org/abs/2611.34436)

- **方法**：多模态知识图谱 + 领域自适应概念词表 + 概念中介偏好
- **结果**：在共享概念上 grounding 用户偏好，支持跨 item 复用

### C1 ★★★★☆ Meta 发布 TLX：把 warp group、TMA、cluster 暴露给 Triton，H100/B200/MI300 覆盖，6 个 FP16 GEMM 与 cuBLAS 差 -0.9%~+3.7%（11-23）

〔C·算子优化〕

![图源：marktechpost.com 原文配图](https://www.marktechpost.com/wp-content/uploads/2026/11/WP-BLOG-BANNER-1113454-1-scaled.png)

TLX 在 11-10 已报过开源消息；这次是 Meta 的详细技术报告，新增的是下面这组性能数字。Meta 公布了 TLX（Triton Low-Level Extensions）的详细报告，这是 Meta 生产 ML kernel 背后的 GPU 编译器扩展。TLX 在 Triton 之上暴露 5 类能力：warp-group 编排（producer/consumer/epilogue 角色）、硬件 mbarrier 同步、TMA/TMEM/异步 tensor core 访存、cluster 级分布式共享内存与 barrier、可选 layout 覆盖。支持 Hopper（H100）、Blackwell（B200/GB200）和 AMD MI300/MI350，MIT 协议。报告称：一个 Blackwell GEMM 约 200 行 Python 级 Triton；6 个 H100 FP16 GEMM 形状与 cuBLAS 相差 -0.9%~+3.7%；H100 广告推理的线性压缩 kernel 提速 4 倍；B200 上 dense LLM attention 前向约达 FlashAttention-4 的 87%。数字均为自报，尚无独立 benchmark。 [\[17\]](https://www.marktechpost.com/2026/11/23/meta-tlx-triton-low-level-extensions/)

## 搜索与智能体意图决策

### C4 ★★★★★ arXiv：把「决策列」当索引——每个坐标是一个决策模型对自然语言问题的校准回答（是/否/未提及），检索可逐题解释（11-23）

〔C·搜索与智能体意图决策〕

2611.27910（new）提出可解释嵌入：每一列存一个决策模型对某个自然语言问题的校准回答（yes/no/not stated），一条记录的嵌入就是它在有序问题集上的答案向量。相似度可精确分解到每个问题的贡献；新增问题只加坐标、不改旧坐标，因此不用重编码语料。在公开商品基准上，问题空间检索在 retrieve-then-verify 实体匹配里与稠密候选生成统计相当，同时能对接受的匹配给出精确解释；用检索失败反推的新问题把 MRR 提高到约 3 倍且无需重编码。搜索侧，推断「合适结果应具备的属性」优于只编码字面请求；问题空间与稠密分数融合有提升但未达预设置信阈值。另有一个小网络从已有稠密向量预测整条可解释向量，可用几千条标注回填语料。 [\[20\]](https://arxiv.org/abs/2611.27910)

### C5 ★★★★☆ ERA：跨模型潜在检索的冷启动适配 + 1.2ms 路由器，难查询才升级，端到端 160ms 降到 38–86ms（11-23）

〔C·搜索与智能体意图决策〕

![图源：arxiv.org 论文首图](https://arxiv.org/html/2611.26919v1/figures/candidate_1.png)

2611.26919（new）解决生产检索系统被索引时的 embedding 模型绑死的问题：换 encoder 通常要全量重编码，冷启动又没有查询日志。ERA 用 Cosine Farthest Point Sampling 从目标索引里挑少量最有信息量的文档作锚点，训练带 Manifold Alignment Loss 的轻量 adapter（方向对齐 + 正交正则防坍缩），再配一个确定性路由器，只把少量难查询升级到更强的编码器。五个 BEIR 数据集上不劣于逐点 L2 与向量转换基线，Arguana nDCG@10 最高相对提升 35%。adapter+路由开销 1.2ms（本地编码器约 20ms）；20% 名义升级预算下，端到端延迟从约 160ms 降到 38–86ms，且升级集中在投影失败最多的查询上。 [\[21\]](https://arxiv.org/abs/2611.26919)

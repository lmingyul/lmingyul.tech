## Search & agent intent

### C1 ★★★★★ Procedure Inference as Memory: navigating hiring decision procedures with Jev-class models (11-26)

〔C · Search & agent intent〕

![Source: arxiv.org paper figure](https://arxiv.org/html/2611.34576v1/Six_Memory_Strategies_for_Hiring_Assistants.png)

The paper targets multi-session hiring assistants. It proposes OKF-indexed episodic memory to organize interactions, then learns reusable “decision procedures” through prompted reflection or reinforcement learning. Experiments compare no memory, full-history context, and dialogue search, and they evaluate Jev-class models for index navigation, as well as GPT-5.6 Luna as a lower-cost stand-in for GPT-5.4. [\[29\]](https://arxiv.org/abs/2611.34576)

### C2 ★★★★☆ Agentic Waterfall: intent-driven information discovery that returns recommendation control to the user (11-26)

〔C · Search & agent intent〕

![Source: arxiv.org paper figure](https://arxiv.org/html/2611.34407v1/figures/waterfall-interaction-illustrated-v3.png)

The paper formalizes the “Agentic Waterfall Feed” problem: users explicitly specify the direction of recommendations, and the system infers their changing needs from both those requests and browsing behavior. The approach uses a language-model controller to maintain persistent user state and to coordinate retrieval, ranking, and state updates. The authors also release a dataset and a replay-style evaluation protocol. [\[30\]](https://arxiv.org/abs/2611.34407)

### C3 ★★★☆☆ Welfare-Enhancing Mechanism Design for Agent Ecosystems: agents pick content sources before seeing the documents (11-26)

〔C · Search & agent intent〕

![Source: arxiv.org paper figure](https://arxiv.org/html/2611.33627v1/fig3_mechanism_banner.png)

The paper studies a multi-agent content market on the Agentic Web: a user agent can only decide whom to query from the profiles submitted by content agents, before it can see the documents themselves. The authors build the WildRegistry simulation framework and a benchmark, and analyze strategy and welfare when multiple content agents compete for limited exposure. [\[31\]](https://arxiv.org/abs/2611.33627)

# E. Paper picks

## Search, ranking & recommendations

### E1 ★★★★★ Alibaba LazUnirec: LoRA-MoE + uncertainty estimation, putting retrieval and ranking into the same backbone (11-26)

〔E · Search, ranking & recommendations〕

*🏛 Alibaba · see paper · arXiv 2611.32590 · 11-26*

Alibaba proposes LazUnirec, which unifies retrieval and ranking in multi-scenario recommendation: LoRA-modulated attention plus a task-adaptive sparse MoE to build shared and private parameters, with uncertainty estimation guiding the direction of gradient updates. The system is already live in multiple scenarios, with positive online A/B results. [\[40\]](https://arxiv.org/abs/2611.32590)

- **Method**: LoRA-modulated attention + task-adaptive sparse MoE + uncertainty-guided gradients
- **Results**: already live in a multi-scenario system, with positive online A/B results

### E2 ★★★★☆ Etsy SIDECAR: draft + tree-attention in a single forward pass, replacing L rounds of beam search (11-26)

〔E · Search, ranking & recommendations〕

*🏛 Etsy · see paper · arXiv 2611.32855 · 11-26*

To cut the cost of the fixed L sequential decoding steps in SID generative retrieval, Etsy proposes SIDECAR: draft candidates first, then score the whole tree in one tree-attention pass, with exact top-K certification and a branch-and-bound fallback. When the model is relatively sharp, only a few calls are needed to return an exact top-K. [\[41\]](https://arxiv.org/abs/2611.32855)

- **Method**: draft candidates + a single tree-attention scoring pass + exact top-K certification
- **Results**: replaces L sequential decoding steps; when the model is sharp, a few calls return an exact top-K

### E3 ★★★★☆ Tencent OmniEVIE: a 4.5B multi-vector embedding model, 54.2ms single-thread queries over a million records (11-26)

〔E · Search, ranking & recommendations〕

![Source: arxiv.org paper figure](https://arxiv.org/html/2611.32203v1/figures/fig1_overview.png)

*🏛 Tencent · see paper · arXiv 2611.32203 · 11-26*

Tencent released OmniEVIE, a 4.5B multi-vector embedding model that unifies retrieval over text, images, visual documents, video, and tools. Each record is compressed to 128×int8×d64 (9,472 bytes). It scores 60.06 on MMEB-V3, and a single-thread query over a million records takes 54.2ms — 11.1× faster than exact retrieval with 4096-dimensional single vectors. [\[42\]](https://arxiv.org/abs/2611.32203)

- **Method**: multi-vector embeddings + a 128×int8×d64 compressed index

# C. 与你相关

## 算子优化

### C1 ★★★★☆ NVIDIA：长上下文稀疏注意力的融合 indexer / Top-k kernel，复用上一步选择让 Top-k 快 2.1–2.4 倍（11-18）

〔C·算子优化〕

![图源：developer.nvidia.com 原文配图](https://developer-blogs.nvidia.com/wp-content/uploads/2026/11/llm-optimize-deploy.webp)

上下文推到数十万 token 时，稠密注意力在 128K 就占掉大部分 prefill。NVIDIA 讲训练期就写进模型的稀疏注意力：indexer 用带融合 epilogue 的 batched matmul 给全部 key 打分，核心注意力只看 Top-k。要点：KH=1 加跨头规约，避免 decode 随 key head 线性变慢；index 头维 128/256，在 FP16 做 epilogue；把 Top-k 融进 indexer kernel，省掉 logit 写回；用上一步 decode 的选择作猜测，Top-k 加速约 2.1–2.4 倍。文中指向 TensorRT-LLM 的融合 Top-k 和 FlashInfer 的 fused indexer / Top-k 实现。 [\[26\]](https://developer.nvidia.com/blog/co-designing-sparse-attention-for-efficient-long-context-inference/)

### E1 ★★★★☆ IntentFlow：小红书显式建模图文查询意图，让召回和重排用同一套相关性标准（11-17）

*🏛 小红书 · Dongjia Zhao, Yuchen Ma, Chunsheng Shi 等 · arXiv 2611.20448 · 11-17*

图文查询的相关性取决于用户的检索意图，只靠视觉或主题相似不够；先视觉检索再重排也不行，因为符合意图的笔记可能根本不在初筛集合里。 [\[37\]](https://arxiv.org/abs/2611.20448)

- **方法**：显式建模图文查询的检索意图，让候选召回和重排在同一相关性标准下对齐。

- **结果**：已在 Meta 端到端部署，量化指标见原文。

## Agent 与 GUI

### E3 ★★★★☆ EchoSpec：训练搜索 Agent 看重主证据而不是转述「回声」，并保住弃答能力（11-17）

〔E·Agent 与 GUI〕

*🏛 （单位见原文） · Shihao Yang, Can Zeng, Xinzhe Li · arXiv 2611.20034 · 11-17*

RL 训练的搜索 Agent 会把同一说法的大量转述当成独立证据，真正能定案的主来源往往只出现一次，Agent 还会丢掉弃答能力。 [\[39\]](https://arxiv.org/abs/2611.20034)

- **方法**：训练 Agent 按证据而不是回声加权，并保留弃答。
- **结果**：主证据仍在的多跳维基问题上，8 条转述的错误声明就能推翻先前 58–73% 的正确答案；EchoSpec 的改善数字见原文。

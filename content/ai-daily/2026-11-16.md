〔B·推理与训练框架〕

![图源：marktechpost.com 原文配图](/uploads/ai-daily/2026-11-16/B3.webp)

Google Cloud 开源 C++ 库 TPU Sync，把 TPU HBM、主机 DRAM、共享存储和网络当作一层内存层次，专门搬 KV cache 和模型权重；报道称在 235B–480B 模型上 KV 传输延迟降低超过 90%。 [\[19\]](https://www.marktechpost.com/2026/11/13/google-tpu-sync-kv-cache-transfer-library/)

> 🎯 **对你**：推理服务里 KV 搬运瓶颈的参考，不是可直接用的 CUDA/Triton kernel。

### B4 ★★☆☆☆ Cmpnd 发布 dspy-wsp：在 DSPy 里让前沿模型直接编辑另一模型的权重（11-15）

〔B·推理与训练框架〕

![图源：marktechpost.com 原文配图](/uploads/ai-daily/2026-11-16/B4.webp)

> 🎯 **对你**：后训练之外的模型编辑思路，离 ms-swift 主路径较远。

## Agent 与工程框架

### B6 ★★★★☆ SparseRead：让 Agent 先判断“读不读、读哪里”，称最高省 92.9% Token（11-13）

〔B·Agent 与工程框架〕

SparseRead 在内容进入上下文之前先判断哪些值得读：先明确阅读意图，再针对代码、长文档、表格按需定位证据并控制阅读预算，必要时回退完整读取。项目称最高省 92.9% Token、少 89% 耗时且质量不降，数字来自项目说明，需对照仓库核实。 [\[22\]](https://github.com/Liuzedooong/SparseReading)

> 🎯 **对你**：“先判断读不读”接近证据充分性门控，可看它的评测设定，考虑用在长文档任务和自由游走采集。

Perplexity 发布 pplx-decider-v1.3（约 27B，基于 Qwen3.8-27B）和 pplx-decider-flash-v1.3（约 4–5B），明确说受 TypeSafe Jev 启发：不生成长文本，对是/否、多选和打分题直接输出选项概率。新能力 Locate 按字段或指令抽出带起止偏移的文本 span，面向 NER、PII 和抽取式问答。权重 Apache 2.0，也可走 Decisions API 和 OpenRouter。 [\[29\]](https://www.marktechpost.com/2026/11/13/perplexity-decider-v1-3-open-weight-decision-models-locate/)
- 自报：63 项查询分类平均准确率 91.6%；72 项检索/重排平均 nDCG@10 83.99，比 Qwen3-Reranker-8B 高 1.81、比 Jev 1.14 高 2.24；Locate 17 个域外任务均分 69.0。
- 答案翻转率 0.27%，每百万生产请求 26.47 美元；Flash 在金融、编程、法律上落后 Jev 1.14。

> 🎯 **对你**：可把 Decider/Jev 作为搜索意图路由、重排和证据充分性的候选 System-1，开源权重可以直接拉到内部测；重点自己测校准（ECE）、延迟和金融域效果，别只看自报均分。

### C3 ★★★★★ CURATOR：微调决策模型，在大量候选 span 上联合选择 RAG 证据（11-14）

〔C·搜索与智能体意图决策〕

![图源：arxiv.org 论文首图](/uploads/ai-daily/2026-11-16/C3.png)

论文 CURATOR（Shib Dasgupta、Bandish Parikh、Rashmi Gangadharaiah，工业界）指出 RAG 常把整段召回塞给 LLM，真正有用的只是少数 span；预训练决策模型能一次对多个 span 做去留判断，但候选变多时判别力下降。CURATOR 在不同规模候选池上微调决策模型，联合决定保留哪些证据 span，称跨任务与文档域可泛化，在上下文受限时提升下游 RAG 效果。 [\[30\]](https://arxiv.org/abs/2611.16366)

> 🎯 **对你**：正好是“证据够不够、哪些 span 该留”的 System-1 门控做法；重点看它怎么解决候选变多后决策质量下降，以及与 LLM 重排器在延迟和上下文预算上的对比。

### C4 ★★★★☆ AWS：用 NVIDIA NeMo Switchyard 给编码 Agent 请求做模型路由，成本按整段任务算（11-14）

〔C·搜索与智能体意图决策〕

![图源：aws.amazon.com 原文配图](/uploads/ai-daily/2026-11-16/C4.png)

# E. 论文精选

## 搜索、排序与推荐

### E1 ★★★★☆ ReSID：从 SID 构建、解码、匹配全链路提升生成式推荐长尾可达性，已上主流量（11-14）

〔E·搜索、排序与推荐〕

![图源：arxiv.org 论文首图](/uploads/ai-daily/2026-11-16/E1.png)

*🏛 阿里巴巴 · Muyu Zou, Shunye Tang, Yi Xu 等 · arXiv 2611.16404 · 11-14*

生成式推荐里长尾物品经常“找不着”：顺序 SID 在尾部表现差，束搜索剪枝又让解码失败无法恢复。 [\[43\]](https://arxiv.org/abs/2611.16404)
- **方法**：并行长 SID + 去偏且感知用户语义的 beam + 部分匹配。
- **结果**：称长尾检索 SOTA，窄 beam 下延迟更低、吞吐更高；已服务主流量，开源代码和 checkpoint。

> 🎯 **对你**：如果搜索召回在试生成式检索，可直接参考它对尾部可达性和束搜索剪枝的分析。

### E2 ★★★★☆ AntEmbed：同一索引兼顾快速检索与推理增强细粒度匹配，MMEB-v2 81.5（11-14）

〔E·搜索、排序与推荐〕

![图源：arxiv.org 论文首图](/uploads/ai-daily/2026-11-16/E2.png)

*🏛 蚂蚁集团等 · Kehang Jia, Teng Liu, Juntao Li 等 · arXiv 2611.16405 · 11-14*

判别式嵌入快但粗，带推理的生成式嵌入细但贵，通常要两套索引。 [\[44\]](https://arxiv.org/abs/2611.16405)
- **方法**：多正例对比学习 + 跨模式自蒸馏，把两种模式统一到一个嵌入空间、共享一份候选索引，推理信息蒸馏进判别表征。
- **结果**：AntEmbed-8B 在 MMEB-v2 总分 81.5，比最强基线高 3.1。

> 🎯 **对你**：“检索快路径 + 细匹配慢路径、索引只一份”的做法，可借鉴到搜索的召回与精排分层。

### E3 ★★★★☆ TriGen：点击触发推荐的生成式范式，动态门控即时意图与长期偏好，已全量（11-14）

〔E·搜索、排序与推荐〕

![图源：arxiv.org 论文首图](/uploads/ai-daily/2026-11-16/E3.png)

*🏛 工业界（与 ReSID 同团队） · Muyu Zou, Haibo Xing, Shunye Tang 等 · arXiv 2611.16395 · 11-14*

用户点击后立即刷新的推荐，既要对齐当前点击意图，又不能丢掉长期偏好。 [\[45\]](https://arxiv.org/abs/2611.16395)
- **方法**：校准的尾部注入 + 动态门控仲裁即时意图与长期偏好 + 位置特定变换引导解码。
- **结果**：六国市场在线 A/B 收入与 GMV 显著提升，已全量部署。

> 🎯 **对你**：“即时意图 vs 长期画像”的门控，和搜索里短时上下文与稳定画像的融合是同一类问题。

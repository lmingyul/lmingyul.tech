## 搜索与智能体意图决策

### C1 ★★★★☆ 腾讯 WePocketModel：一套端侧共享底座同时做生成、嵌入和结构化决策，内存省 61.9%（11-24）

〔C·搜索与智能体意图决策〕

![图源：github.com 原文配图](https://opengraph.githubassets.com/e45e5604025030d2f16ba0cda527e60643862c51e9c59bfa73925245290d50b4/Tencent/WePocketModel)

腾讯开源 WePocketModel，用一套共享多模态底座同时完成生成、嵌入和结构化决策，替代手机 App 里常驻多个独立小模型的做法。它用多粒度视觉 Token 分配、跨任务知识蒸馏和多任务优化缓解训练冲突；官方称相比部署三套独立权重常驻内存节省 61.9%。适用离线助手、手机视觉搜索、本地知识检索、智能相册、商品识别。 [\[17\]](https://github.com/Tencent/WePocketModel)

### C2 ★★★★☆ Search Agent 能不能自己改错？给证据也可能不改，关键在“送达决定性段落”（11-24）

〔C·搜索与智能体意图决策〕

论文在 BrowseComp-Plus 上回放模型自己答错的闭卷答案，再干预“什么证据能到达模型”：4 个开放权重模型、709 题、26,665 个测试条件。一个自信的助手先验会让 Nemotron 的配对准确率下降 16.1 个百分点，即使答案段落就在上下文里；用户坚持原答案时再降 32.9 / 12.6 点。把决定性段落直接放进上下文，比中性投递分别提升 Qwen3.5 51.0 点、Nemotron 22.4 点；但 Nemotron 仍有 19/51 个 episode 耗尽搜索预算没给答案。 [\[18\]](https://arxiv.org/abs/2611.30243)

### C3 ★★★☆☆ NoeVera：决策感知检索 + 模拟器，6–7 次实验就逼近最优配置（11-24）

〔C·搜索与智能体意图决策〕

![图源：arxiv.org 论文首图](https://arxiv.org/html/2611.29255v1/Figure1_NoeVera_workflow2.png)

NoeVera 是面向 LLM 服务优化的 agentic Second Brain：把论文、代码、benchmark 和实验结果整理成带 provenance 的知识库，分源证据、可复用综合、Agent 记忆三层。决策感知检索组装紧凑证据包，角色化 Agent 推理，需要定量支持时调用 Vidur 或 GAUSS 模拟器，结论再写回成有适用范围的证据记录。四个 serving 场景里，中位 6–7 次模拟调用就进入最优值 5% 以内（贝叶斯优化 9 次、无知识 Agent 15 次）；A100 上代表性配置约 1.30x vLLM 默认吞吐并满足延迟目标；证据复用只在 8% 的适用性陷阱上过度泛化（通用 Agent 记忆 28%）。 [\[19\]](https://arxiv.org/abs/2611.29255)

### C4 ★★★☆☆ TWIML #786：Thore Graepel 谈“不确定性显式化”，小模型与决策模型该放在哪（11-25）

〔C·搜索与智能体意图决策〕

![图源：twimlai.com 原文配图](https://twimlai.com/images/at/shows/twiml-thore-graepel-building-ai-that-can-reason-under-uncertainty-fhd.png)

Thore Graepel（Metis Reasoning CEO、UCL 机器学习讲席）在 TWIML 谈一种受 AlphaGo 启发的推理路线：可靠推理需要显式表示知识与不确定性，语言模型负责生成假设和解释证据；系统把复杂问题拆开、收集证据，再按“预期能消除多少不确定性”选择下一步。他明确讨论了这与 Agent harness 的区别，以及更小的模型和决策模型可以放在哪一层。 [\[20\]](https://twimlai.com/podcast/twimlai/building-ai-that-can-reason-under-uncertainty)

# E. 论文精选

## 搜索、排序与推荐

### E1 ★★★★☆ PROSPER：LLM 做稀疏检索，保留品牌/型号字面信号，已上工业混合检索 A/B（11-24）

〔E·搜索、排序与推荐〕

![图源：arxiv.org 论文首图](https://arxiv.org/html/2611.28645v1/case_table.png)

*🏛 中科院计算所 · 阿姆斯特丹大学 · Hongru Song, Yu-An Liu, Ruqing Zhang 等 · arXiv 2611.28645 · 11-21*

商品搜索的一阶段召回要在高召回和可部署之间取舍：稀疏检索可解释、易上线，但短查询和商品标题的词表不匹配很严重；直接用 LLM 做稀疏扩展又会把品牌名、型号等关键的字面信号改掉。 [\[26\]](https://arxiv.org/abs/2611.28645)

- **方法**：用“字面残差网络”给被 LLM 稀疏扩展压低的字面词（品牌、型号）做残差补偿，再用“词法聚焦窗口”做 top-k 早稀疏和训练初始化。
- **结果**：离线评测和较大规模线上 A/B 都优于现有稀疏检索，并在工业混合检索里带来收入增益（作者自报，具体数字见原文）。

### E2 ★★★★☆ abc index：只靠经典 IR 技术做精确稀疏检索，比 Qdrant 精确搜索快 6.5–84 倍（11-24）

〔E·搜索、排序与推荐〕

*🏛 比萨大学 · Rossano Venturini · arXiv 2611.28555 · 11-21*

学界普遍认为 learned sparse retrieval（LSR）上经典动态剪枝失效、精确索引不如 Seismic/HNSW 近似索引快。 [\[27\]](https://arxiv.org/abs/2611.28555)

- **方法**：只组合标准 IR 技术：term-at-a-time 求值、Block-Max MaxScore、二进制打包、doc-id 重排，并针对现代 CPU 做工程优化。
- **结果**：MS MARCO 上四个 LSR 模型，abc 是每个 k 下最快的精确索引：比 Qdrant 精确搜索快 6.5–84 倍、比 Lucene 快 13–55 倍；对近似索引 k=10 时最多慢 4.3 倍，k=1000 时反超。

### E3 ★★★★☆ Weight Coding：LLM Agent 直接改推荐模型权重，Pinterest 线上人均收藏 +8.4–10.7%（11-24）

〔E·搜索、排序与推荐〕

![图源：arxiv.org 论文首图](https://arxiv.org/html/2611.29613v1/fig3_effect_map.png)

*🏛 Pinterest · Junpeng Hou, Jiaxing Qu, Derek Cheng 等 · arXiv 2611.29613 · 11-22*

不改架构、不改 serving，直接编辑权重就能拿到线上收益，这是“模型演进”里很少见的一条低成本路径。 [\[28\]](https://arxiv.org/abs/2611.29613)

- **方法**：让 LLM Agent 检查模型结构与参数、提出假设、直接做可执行的权重编辑，用评测反馈迭代；缓存引擎支持不反传的快速前向评估。
- **结果**：Pinterest 1.47 亿参数图像搜索双塔，held-out recall@10 最高 +15.0 个百分点（相对 +24%），约 1/4 的全量后训练 GPU 小时；随机重置 1360 万参数交互模块后搜索 2448 个 mixing/normalization 参数，比生产高 9.8 点；线上 A/B 人均收藏 +8.4%–10.7%。

### E4 ★★★★☆ Meta DepThink：单次前向里做 K 个残差 token 递归，训练快 11.9 倍、推理快 4.3 倍（11-24）

〔E·搜索、排序与推荐〕

![图源：arxiv.org 论文首图](https://arxiv.org/html/2611.26752v1/all_model_alpha.png)

*🏛 Meta · Jiangfan Zhang, Wentao Bao, Xian Wu 等 · arXiv 2611.26752 · 11-19*

想要循环架构的表达力、又不想付顺序迭代的延迟，DepThink 给了一个“并行但带递归”的折中。 [\[29\]](https://arxiv.org/abs/2611.26752)

- **方法**：在单次 prefill 前向里追加 K 个可学习 residual token，hidden state 通过轻量可学习残差递归耦合，让后面的 token 逐步补前面遗漏的信息；理论证明其几何方向可达性严格大于普通 learnable token，并有一阶下降优势。
- **结果**：在 2B/8B dense 与 30B-A3B MoE 骨干上匹配或超过循环架构，训练加速最高 11.9x、推理 4.3x。

### E5 ★★★☆☆ 长文档分层检索：利用原生章节结构，比 flat top-k 在 QuALITY 上高 10.6 个点（11-24）

〔E·搜索、排序与推荐〕

*🏛 机构见原文 · Rohit Singh, Nathaniel Weems · arXiv 2611.29966 · 11-23*

机构见原文； [\[30\]](https://arxiv.org/abs/2611.29966)

- **方法**：两级检索，先用章节摘要做 BM25+稠密混合选章，再做章内稠密检索，最后在 token 预算内把 top passages 扩成连续、带 section 的 span；用内容哈希门控做增量 ingestion。
- **结果**：QuALITY 上 81.0% vs flat top-k 70.4%（p=0.0019），与全文上界无显著差异；NovelQA 55.7% vs 56.8%（统计打平）；增量编辑可复用 94–99.7% 的 embedding。

## RL 与后训练

### E6 ★★★★☆ CO-GRAFT：把搜索 Agent 的 RL 收益拆到四个角色，查询生成最多只占 15%（11-24）

〔E·RL 与后训练〕

![图源：arxiv.org 论文首图](https://arxiv.org/html/2611.31185v1/figs/fig_mechanism.png)

*🏛 机构见原文 · Ramraj Chandradevan, Sayontan Ghosh, Vinoth Selvendran · arXiv 2611.31185 · 11-23*

CO-GRAFT 用角色级策略嫁接做干预归因：RL 后的 Agent 与 RL 前初始化在同一条闭环轨迹上各控制互斥的角色——中间推理、搜索或回答的决策、查询生成、最终答案抽取。 [\[31\]](https://arxiv.org/abs/2611.31185)

- **方法**：角色级策略嫁接：RL 后与 RL 前的模型在同一条轨迹上分别控制推理、搜索决策、查询生成、答案抽取四个角色，枚举 16 种组合，用 Shapley 值分解收益。
- **结果**：在 Search-R1（Qwen2.5/Llama-3.2、GRPO/PPO、NQ/HotpotQA）上，查询生成从未超过总收益的 15%；收益主要由 RL 前答案有效性、搜索保留率、模型规模和搜索预算决定。

# C. 与你相关

## 搜索与智能体意图决策

### C1 ★★★★★ Gemini API 上线 Tool Retrieval：Agent 先检索工具名，再按需加载 schema（11-20）

〔C·搜索与智能体意图决策〕

![图源：blog.google 原文配图](https://storage.googleapis.com/gweb-uniblog-publish-prod/images/Tool_retrieval_hero.width-1300.png)

Google 在 Gemini Interactions API 预览推出 Tool Retrieval。Agent 挂几十上百个工具时，每次把所有 schema 放进提示会抬高 token 和延迟，候选越多选得越不准。新机制加了一个 tool_search 工具，长尾工具设 defer_loading=true：模型先检索工具名，服务端再加载对应 schema 并发出 function_call；常用工具仍可预加载。不用自建索引，兼容前缀缓存和远端 MCP（对 mcp_server 设 defer_loading 后其工具也按需加载）。适用于 Gemini 3.6 及以后模型。官方没有给出选择准确率或 ECE 的对比数字。 [\[28\]](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/)

### C2 ★★★★☆ MARS：用 0.6B 近线 Agent 为每个用户编排推荐管线的通道、配额和模型选择（11-19）

〔C·搜索与智能体意图决策〕

![图源：arxiv.org 论文首图](https://arxiv.org/html/2611.24006v1/fig_abstract.png)

MARS（Multi-stage Agentic Recommendation System）技术报告指出：工业推荐的检索、粗排、精排、重排多级漏斗里，通道开关、配额、模型选择和分数融合大多由工程师按场景统一配置，对用户没有个性化。作者用微调的 Qwen3-0.6B 做近线 Agent，为每个用户生成管线编排，把个性化从单点打分扩展到整条漏斗的路由决策。46 页，arXiv 2611.24006。 [\[29\]](https://arxiv.org/abs/2611.24006)

## GUI Agent 与任务执行

### C3 ★★★★★ Perplexity Brain 从会话里自动生成 Agent Skills：8 周对照实验工具调用失败率降 11%（11-20）

〔C·GUI Agent 与任务执行〕

![图源：x.com 原文配图](https://pbs.twimg.com/media/HXgB910a4AAzs66.png?name=orig)

Perplexity Computer 的自改进 Agent「Brain」开始自动为用户生成并更新 Agent Skills（可复用的流程指令，相当于程序性记忆）。流程四步：从历史会话找证据 → 改进 Agent 读完整会话提出修改 → 校验（全局技能修订须通过全部测试场景、原版至少挂一个、工程师审批；个人技能走确定性检查 + LLM judge 抽检）→ 应用；证据不足就不改。8 周线上随机对照：实验组 72.9% 用户新增至少一个个人技能（对照组手动添加仅 6.5%），工具调用失败率降 11%（去掉后台任务约降 7%），中高不满意会话每用户降 7.6%，成本和响应时间无明显变化。已对美国全部个人和企业订阅用户默认开启。 [\[30\]](https://x.com/perplexity_ai/status/2123449395882701224)

## 搜索、排序与推荐

### E1 ★★★☆☆ X-split Argus：把用户历史压成可离线复用的 token，做低延迟 CTR 预估（11-19）

〔E·搜索、排序与推荐〕

*🏛 机构见原文 · Alexander Ploshkin, Nikita Stepanov, Alexey Pismenny 等 · arXiv 2611.24283 · 11-19*

候选很多时不能对每个候选重算整段用户历史，延迟扛不住。 [\[40\]](https://arxiv.org/abs/2611.24283)

- **方法**：压缩器把历史交互编成一组可离线计算、跨候选复用的 token，在线打分器对这些 token 做 cross-attention，两者端到端训练。
- **结果**：摘要称在生产延迟约束下同时保留长期偏好和近期意图，具体数字见原文。

### E2 ★★★☆☆ 方差最优的反事实策略设计：让在线 A/B 更快看出小效应（11-19）

〔E·搜索、排序与推荐〕

*🏛 机构见原文 · Shashank Gupta, Subhadeep Maji · arXiv 2611.24757 · 11-19*

标准 A/B 的均值差估计无偏但方差高：新老策略对同一动作概率相近时，这些样本贡献很少却加噪声，小效应要很久才看得出。 [\[41\]](https://arxiv.org/abs/2611.24757)

- **方法**：设计方差最优的反事实策略，提高在线 A/B 的样本效率。
- **结果**：摘要未给具体数字，见原文。

- **方法**：CONCORD-Rec 用反事实目录划分效用判断各模态是否真降低语义 ID 歧义；ReflectRec（EMNLP 2026）给 CoT 推荐加「偏好笔记 → 历史」回查，可恢复性低时重新生成；VIBRA 用多视图共识重心做向后兼容跨模态检索，升级编码器不必重编码旧库。
